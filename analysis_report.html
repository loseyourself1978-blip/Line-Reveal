🔍四、PRD 对比分析 — 已识别差距
  • ⏱️
    缺少倒计时机制
    P0 致命
    PRD 要求每关 120 秒限时，剩余 30 秒视觉变红、倒计时音效加速，超时游戏结束。当前代码中 GameEngine 无任何定时器逻辑，HUD 无倒计时显示，关卡可无限时间游玩。
    PRD §3.1: "计时器：120秒，剩余30秒闪烁红色，超时结束游戏"
  • 🎮
    玩家起点与交互锚点偏差
    P0 致命
    PRD 定义玩家从屏幕左边缘中点出发，以红色实心圆标记（大小随手指压力变化）。代码实现为底部中央出发，黄色圆点，无压力感知。这直接影响初次用户理解核心操作。
    PRD §2.1: "起始点：屏幕左侧边缘中点；玩家标记：红色实心圆"
  • 👾
    精灵行为与 PRD 不符
    P0 致命
    PRD 定义 3 种精灵：慢速 (1.5x)、瞬移 (随机跳跃)、弹跳 (遇边界反弹) ，视觉为荧光绿/品红/蓝色描边。代码实现为 basic/spider/scorpion/butterfly 共 4 种，缺少瞬移机制，弹跳逻辑也未完全对应 PRD 行为规格。
    PRD §3.3: 精灵类型分类与移动行为规格
  • 🔁
    缺少"撤回"功能
    P1 重要
    PRD 要求每局提供 1 次撤回操作（双击/摇一摇触发），可取消最近一段描线。代码中无任何撤回逻辑，也无对应 UI 按钮。
    PRD §2.3: "每局游戏提供1次撤回机会"
  • 🚫
    无效圈定未检测
    P1 重要
    PRD 要求当玩家画出的封闭区域内不含任何迷雾时，视为无效操作并给出提示。当前 finishDrawing() 仅用大精灵位置判断保留哪块多边形，无法识别"空圈"情形。
    PRD §2.2: "闭合区域内无迷雾则无效并提示"
  • 🧩
    关卡内容未完成（占位 17-30）
    P1 重要
    levels.ts 中第 17-30 关均为复制粘贴的占位模板（id/title 为 "Level X Placeholder"），配置参数未调优，不具备正式发布条件。共 46.7% 关卡为空内容。
    PRD §4: 需完整 4 章共 30 关内容设计
  • 🖼️
    收藏馆 / 碎片 UI 未实装
    P1 重要
    PRD 定义 6 主题系列 × 9 张图 = 54 张作品收藏体系，碎片解锁高清版，画廊支持全屏查看、分享、收藏。代码中 Gallery 路由存在但仅为基础展示，碎片兑换和高清解锁逻辑缺失。
    PRD §5: 完整图鉴与碎片解锁体系
  • ✨
    关键视觉特效缺失
    P2 体验
    PRD 要求：磁吸闭合提示（距起点 20px 内出现绿色圆圈）、描线彩虹渐变、划破迷雾粒子爆炸效果、迷雾消散帧动画。当前仅有基础线条渲染和 Sobel 边缘，无粒子系统，无磁吸提示。
    PRD §6.2: 视觉反馈细节规格
  • 🔒
    首次启动隐私授权弹窗缺失
    P2 体验
    PRD 合规要求首次启动展示隐私政策对话框（用户同意后才能继续）。当前 App 直接进入欢迎屏，无任何隐私授权流程，App Store 审核中可能触发 4.1 拒绝。
    PRD §合规: "首次启动隐私政策弹窗"
  • ☁️
    无云端存档与设备迁移
    P2 体验
    存档仅依赖 localStorage，换手机/重装即丢失所有进度。PRD 要求提供 iCloud 或账号云同步选项。
    PRD §8: 数据同步与备份
  • 📱
    社交分享功能不完整
    P3 增强
    PRD 要求胜利后可生成带解锁进度的分享图片，支持微信/微博等。Capacitor Share 插件已安装，但 ResultScreen 的分享按钮仅为 UI 占位，无实际截图合成逻辑。
    PRD §7: 分享与社交功能

⚠️六、风险评估
🔴 审核拒绝风险 — 隐私政策缺失
Apple App Store 审核要求首次启动必须展示隐私政策。当前直接进入游戏，有较高概率触发 Guideline 5.1.1 拒绝。上线前必须修复。
🔴 用户流失风险 — 无计时器导致无紧迫感
缺少 120s 倒计时使游戏失去核心张力。PRD 文档中时间压力是"天蚕变"体验的关键设计，没有它，游戏趋近于"无聊的涂鸦工具"。
🟠 内容不足风险 — 46% 关卡为占位
约 14 关为占位模板，玩家完成前 16 关后即遭遇内容墙，极高跳出率风险。发版前需确保至少有 25 关真实内容。
🟠 存档丢失风险 — localStorage 无备份
用户重装 App 或清除浏览器数据将丢失所有进度。对于重度玩家（解锁大量内容）这是致命体验问题。
🔵 性能风险 — Sobel 算法在低端设备
Sobel 边缘检测在每次图片加载时执行像素级计算（潜在 O(n²) 复杂度）。低端 Android 设备可能卡顿。需加入结果缓存机制。
🔵 多边形精度风险 — 极端路径场景
splitPolygon() 在玩家画出极复杂或自交路径时的边界行为未经充分测试。可能导致崩溃或迷雾状态异常。需要 fuzz 测试覆盖。

💡九、总结与建议

综合评价

《划线解锁神图》已建立起一套技术上扎实的混合型游戏基础架构。Capacitor + React + Canvas 的组合在移动端性能与开发效率上取得了良好平衡，自研的多边形分割引擎和 Sobel 边缘检测算法是真正的技术亮点，也是与同类游戏形成差异化的核心壁垒。

然而，目前实现与 PRD 设计之间存在约 49% 的功能缺口，尤其是三个 P0 级别的核心玩法缺失（倒计时、正确起点、精灵行为），以及首次启动隐私政策弹窗的合规缺失，在当前状态下不具备上线条件。

建议按上述 8 周计划推进，前两周集中攻克 P0 问题（预估 10-12 人天工作量），第 3-4 周补全 P1 体验缺口，第 5-6 周做视觉打磨，最后两周做 QA 和上线准备。完成后该产品将具备在 App Store 上产生良好口碑的内容深度与技术质量。
